## 统一实施规则

- 固定目录按当前 Windows 用户划分，不跟随 EXE 移动；歌曲、设置、快照、日志均使用同一根目录。
- 最新版选择采用数值版本号，不能用文件修改时间或文件名判断。
- 自动切换覆盖实现了新启动协议的版本。完全未修改的旧 EXE 不会凭空具备跳转功能。
- 发现范围固定为：受管版本目录、已登记来源、当前 EXE 目录、默认安装目录、桌面、下载目录，以及用户登记的搜索目录。搜索只读取候选程序的身份和版本，不启动候选来探测。
- 数据保存未确认成功时取消切换；不能以超时为理由直接强杀。
- 不用“创建歌曲的时间”断言其实际播出时段，不按时段行号推测身份。

## 按以下顺序执行

### 1. 完成固定目录和旧数据迁移

主要文件：`GoServer/paths/paths.go`、`GoServer/services/fixed_data.go`、`GoServer/main.go`、`GoServer/internal/repo/repo.go`。

- [ ] 对来源做完整数据结构校验，并检查歌曲引用的资源文件；迁移完成前保留全部来源。
- [ ] 补迁移来源选择入口：多份不同数据时列出路径、各歌单数量及日期范围，由用户选择来源，不能只留下一个命令行报错。
- [ ] 固定目录已有数据时，仍记录新发现的旧数据来源，并提供比对、导入入口；避免直接忽略旧目录里的本周播音歌单。默认保持固定目录内容，导入前备份；相同 ID 内容不同的记录必须显式处理冲突。
- [ ] 迁移失败或中断不能产生可被当成完整数据库加载的目标；重复执行不能破坏已有数据或备份。
- [ ] 核查旧音频布局迁移与周文件夹重建，确保迁移后歌曲可播放、可导出。

验收：从两个不同目录启动均读同一数据库；旧播音、宿舍、时段和音频完整继承；冲突不覆盖；中断可重试。

### 2. 补全版本发现与启动协调

主要文件：`GoServer/launcher/versions.go`、Windows 平台辅助代码、`GoServer/main.go`。

- [ ] 补以上规定目录的候选发现，读取 Windows EXE 产品标识及版本，验证后登记；现有代码只能选择已经启动登记过的版本。
- [ ] 候选经验证后保存到受管版本目录；登记原始来源目录，供后续查找旧数据。源程序移走或下载目录清理后仍可使用已登记最新版。
- [ ] 校验版本登记内容；文件缺失、哈希不符、登记文件损坏时保留错误证据，避免启动循环或错误覆盖。
- [ ] 将正式版跨路径启动和数据占用协调改为按用户及固定数据目录标识的 Windows 命名互斥量，开发/测试使用独立标识。
- [ ] 返回运行实例的 PID、真实 EXE 路径、版本及实例标识；同版重复启动只打开现有页面，较旧启动器跳转后立即退出。

验收：旧协议版启动器能跳转到发现的较新版；两个目录同时双击只保留一个正式实例；已损坏候选不会启动。

### 3. 完成保存后退出的整个流程

主要文件：`GoServer/handlers/handoff.go`、`GoServer/handlers/lifecycle.go`、`GoServer/main.go`、相关后台任务、`Web/src/components/common/AppHeartbeat.vue`。

- [ ] 页面先完成登记再开放编辑；心跳报告待保存状态。正常离开删除登记；失联且可能有未保存内容的页面不能直接当成已保存。
- [ ] 切换时依次执行：页面暂停编辑 → 保存并确认所有草稿/请求 → 后端停止接收写入并排空在途写入 → 等待涉及数据/音频的后台任务 → 确认落盘 → 退出旧实例 → 新实例加载固定数据。
- [ ] 区分“收到关闭请求”与“保存、排空已完成”。当前关闭 API 返回成功时，后台排空尚未结束，不能将它作为强杀依据。
- [ ] 修正 HTTP 关闭超时后仍继续退出的路径；失败时返回明确原因，恢复可操作状态，保留旧实例。
- [ ] 等待目标 PID 实际退出，而不只检查端口释放。如果已经取得该实例的保存完成确认但进程仍残留，只允许结束已验证的目标 PID；禁止按进程名批量结束。
- [ ] 无新协议的旧版显示明确的保存、托盘退出指引，首次升级不能承诺自动保存它的浏览器草稿。

验收：刚输入歌名立即启动新版，切换后内容仍在；两个标签页均完成保存；写盘失败、断网、后台任务未完成时切换停止。

### 4. 补草稿恢复和保存队列边界

主要文件：`Web/src/utils/pendingSaves.ts`、`Web/src/utils/persist.ts`、播音/宿舍编辑组件、API 客户端。

- [ ] 增加草稿读取及恢复入口。现有随机客户端键只写不读，刷新后备份不会自动进入保存队列。
- [ ] 草稿记录歌单类型、歌曲 ID、数据库标识、原始值及时间；恢复时核对服务器现值。已删除记录或不同页面冲突不能直接自动覆盖。
- [ ] 完成恢复/丢弃后才清理备份；遵循项目统一 localStorage 封装。
- [ ] 无 `crypto.randomUUID()` 的浏览器使用兼容 ID，保证局域网 HTTP 页面可启动。
- [ ] 覆盖连续输入、慢响应、保存失败、删除歌曲、页面切换及强制刷新后的恢复。

验收：不失焦也会保存；较早响应不会覆盖最新输入；刷新可找回草稿；失败时有可重试内容。
